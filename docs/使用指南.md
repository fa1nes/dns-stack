# dns-stack 使用指南

## 一、这套东西是什么

一个自建的 DNS 解析服务，对外提供 **DoH / DoH3 / DoT**。它不转发给任何第三方
公共 DNS，而是**自己从根区完整递归**，并且按**递归出口**分流：

```
客户端 ──DoH(443)/DoT(853)──> 国内服务器 mosproxy
                                  │
                                  ├─ manual-gfw.txt ─> 香港递归器(仅少数特例)
                                  └─ 其余全部 ─> 本机 Unbound 从根区完整递归
                                                    │  每一跳都在问权威服务器，
                                                    │  出口按该权威的 IP 归属分流：
                                                    ├─ 权威在大陆   ─> 直连查询
                                                    └─ 权威在境外   ─> 经香港隧道查询
```

**为什么这样设计**：递归时问的是权威服务器。权威在墙内就直连问(境内到境内，
GFW 不污染)；权威在墙外就走隧道问(GFW 根本看不见这个查询)。两条路径都拿不到
污染答案——污染因此不是"需要检测的现象"，而是**结构上不可能发生**。

判据也从主观的"这个域名算不算国内的"(要人工维护、永远滞后)变成客观的
"这台权威服务器在哪"(客观网络事实，可自动获取)。

还有一层：**只要递归链中任何一级出现墙内 IP，整个域名就走直连解析**。因为一个
域名如果在大陆部署了权威，说明它有意服务国内用户，用国内出口去问它才能拿到为
国内用户准备的 CDN 调度结果。qq.com 就是这样——它 4 台权威里 3 台在海外，走隧道
问会被导向 `ns-os*`(overseas)分支，最终拿到香港节点；直连问才会走 `ns-cnc*`
分支拿到国内节点。

## 二、客户端怎么配

**DoH 地址**

```
https://<你的服务器IP>/<你的私密路径>/dns-query
```

⚠️ 真实地址**不写进本文档**（这个仓库可能被推到远端，写进去等于泄露）。查看方式：

```bash
sudo dns-stack doh-path        # 服务器上执行，直接打印完整接入地址
```

或者打开面板 →「服务与运维」→「DNS 接入地址」，点「复制地址」。

**DoT 地址**

```text
tls://<你的服务器IP>:853
```

**为什么路径是随机的**

DoH 监听在公网 443，而 Let's Encrypt 的 IP 证书会进入 **Certificate Transparency
公开日志**——"这个 IP 上有 TLS 服务"是公开可查的事实，藏不住。扫描器拿到 IP
后固定去探默认的 `/dns-query`，探到就能把你的服务器当免费公共 DNS 用（实测过，
确实能用）。换成 128 位随机路径后，任何人探到的都是 404，与一个空 web 服务器
无法区分。路径在 TLS 内部传输，网络中间人也看不到。

怀疑地址泄露时随时可以换：面板「轮换私密路径」按钮，或 `sudo dns-stack doh-path --rotate`。
换完**所有客户端都要同步更新**，否则会立刻解析失败。

其它注意点：

- 用的是 **Let's Encrypt 的 IP 证书**（SAN 就是那个 IP），所以**必须按 IP 访问**，
  不要自己编一个域名指过去，那样证书校验会失败。
- TCP 与 UDP 的 443 支持 **DoH（HTTP/2）和 DoH3（QUIC）**，TCP 853 支持 **DoT**。
- 证书有效期只有约 7 天，`dns-stack-renew-cert.timer` 每 6 小时检查并通过
  standalone HTTP-01 自动续签；云安全组/边界防火墙必须放行 TCP 80，但该端口平时没有
  常驻监听，只在 ACME 挑战期间短暂使用。

### sing-box

```json
{
  "dns": {
    "servers": [
      {
        "tag": "self-doh",
        "address": "https://<你的服务器IP>/<你的私密路径>/dns-query",
        "detour": "direct"
      }
    ]
  }
}
```

`detour` 用直连即可——分流已经在服务端做完了，再套一层代理反而多绕一圈。

### Windows 11

因为路径是自定义的，**不能用「自动模板」**（那个只认公共 DNS 的已知模板列表），
要先手工登记模板：

```powershell
# 管理员 PowerShell
netsh dns add encryption server=<你的服务器IP> dohtemplate=https://<你的服务器IP>/<你的私密路径>/dns-query autoupgrade=yes
```

然后 设置 → 网络和 Internet → 以太网/WiFi → DNS 服务器分配 → 编辑 → 手动
→ IPv4 开 → 首选 DNS 填 `<你的服务器IP>`，**DNS over HTTPS 选「打开(手动模板)」**。

### Android 9+

设置 → 网络和互联网 → 私人 DNS —— **这里填不了 IP、也填不了路径**，系统只接受
主机名。Android 上要用支持 DoH 的客户端（如 sing-box / Intra）来配。

### 浏览器（Firefox）

设置 → 隐私与安全 → 启用基于 HTTPS 的 DNS → 自定义 → 填上面的完整地址。

### 命令行自测

```bash
DOH="$(sudo dns-stack doh-path | grep ^DOH_URL= | cut -d= -f2-)"
curl -sk -H 'accept: application/dns-json' "${DOH}?name=www.taobao.com&type=A"
```

## 三、日常怎么看、怎么管

### 打开面板

面板已开放公网访问，走 **HTTPS + 密码登录**，端口是随机高位端口：

```
https://<你的服务器IP>:<面板端口>/
```

端口看 `/etc/dns-stack/config.env` 的 `PANEL_LISTEN`。密码在面板「服务与运维」→
「面板访问密码」里改，也可以在服务器上执行 `sudo dns-stack panel-password`。

几条保障：

- 监听非回环地址时，启动脚本会强制检查"已设密码 + 证书可读"，任一不满足就
  **拒绝启动**——宁可面板起不来，也不让一个无密码的特权面板暴露在公网。
- 登录失败按来源 IP 指数退避，防在线爆破；密码以 scrypt 加盐哈希存盘。
- 会话 12 小时过期；改密码会让**其它设备**上的登录状态立即失效。

不想开公网也可以退回隧道模式：把 `PANEL_LISTEN` 改回 `127.0.0.1:8080`，
然后 `ssh -N -L 8899:127.0.0.1:8080 root@<你的服务器IP>`，浏览器开 <http://127.0.0.1:8899/>。

面板能看：实时请求（含每条的真实耗时）、域名统计（请求最多/最近新增/失败最多/解析最慢）、
上游状态、规则与证书、解析测试、各服务日志、服务控制、审计记录、DNS 接入地址管理。

### 常用命令

```bash
sudo dns-stack                    # 交互菜单，不记命令就用这个
sudo dns-stack preflight          # 完整体检，升级/改配置后都该跑
sudo dns-stack health             # 快速健康检查
sudo dns-stack status             # 服务与规则概况
sudo dns-stack test <域名>        # 看某个域名怎么解析、走哪条路
sudo dns-stack doh-path           # 查看 DoH 接入地址
sudo dns-stack doh-path --rotate  # 轮换私密路径(客户端需同步更新)
sudo dns-stack panel-password     # 设置/重置面板密码
```

## 四、想让某个域名换条路走

先分清两类文件，它们**用途完全不同**，混淆会让人以为改了 A 却没生效：

### ① 影响 DNS 解析方向的

| 文件/集合 | 来源 | 用途 |
|---|---|---|
| `manual-gfw.txt` | 你自己 | 强制走香港递归。给"国内权威返回空应答"的域名用(如 `c.mi.com`) |
| `manual-exclude.txt` | 你自己 | 把某域名从上面那条规则里摘出来，回到默认的本机递归 |
| `chnroute/direct4.txt` | APNIC 官方委派记录 | 大陆 IP 段。递归出口据此判定直连还是走隧道，每日刷新 |
| `chnroute/cn-authority.txt` | 自动学习 | 直连域名的权威地址段，每 15 分钟刷新。面板上叫「直连权威地址」 |
| `chnroute/cn-zones-matched.txt` | 自动学习 | 已判为"整条递归走直连"的区域清单，排查时最有用。面板上叫「直连域名」 |
| `manual-cn-zones.txt` | 你自己 | 人工补充"应当走直连"的区域 |

**注意没有 `cn.txt`**：DNS 方向不再依赖任何域名名单，出口按权威 IP 归属决定。

### ② 发布给客户端做流量分流的（不影响 DNS）

| 文件 | 来源 | 用途 |
|---|---|---|
| `cn.txt` | 规则构建机(HK)按权威位置判定 | 客户端据此决定哪些域名直连 |
| `gfw.txt` | 同上 | 客户端据此决定哪些域名走代理 |
| `cn-ip-cidr.txt` | 大陆 IP 段 | 客户端遇到裸 IP 连接(没有域名可查)时的判据 |
| `polluted-ip-cidr.txt` | 污染探测 | 已确认的污染地址，供客户端过滤 |

这四份由规则构建机(HK)生成并发布到 GitHub，国内机每 5 分钟同步一次。它们与 DNS 解析
方向**用同一套判据**(递归链任一级权威在大陆 → 归国内)，所以结论一致，但链路
完全独立——mosproxy 一行都不读。

**某个国内站被解析到了境外节点**：

绝大多数情况不用管——系统每 15 分钟自动学习一次，第二次查询就会自己纠正。只有
持续不纠正时才需要人工补一条：

```bash
echo "example.cn" >> /var/lib/dns-stack/manual-cn-zones.txt
sudo dns-stack routing-refresh    # 立即重建，不必等定时器
```

**某个域名必须走香港**（国内权威不给 A 记录的那类）：

```bash
echo "c.mi.com" >> /var/lib/dns-stack/manual-gfw.txt
sudo dns-stack reload             # 热重载，不中断解析
```

匹配是**域匹配**：写 `taobao.com` 就已经覆盖 `www.taobao.com` 等全部子域。

**注意 CDN 域名**：很多站点的图片/视频在另一个域名下（淘宝在 `alicdn.com`、
B 站在 `hdslb.com`）。新架构下这通常不用管——那些 CDN 域名有自己的权威，会被
独立判定。只有当它的权威**全在境外**、而你确认它该走直连时，才需要把它的注册域
写进 `manual-cn-zones.txt`。

规则改错了可以回滚：`sudo dns-stack rollback`（默认保留最近 5 个版本）。回滚后会保持
当前版本，直到 GitHub 出现更高的 `generated-at`，避免 5 分钟定时同步立即覆盖回滚。

数据库结构升级使用 `sudo dns-stack migrate-db`。命令会先创建一致性备份，再短暂停止
数据库写入者、幂等升级并执行完整性检查，不会删除旧数据库。

路由基线被确认污染时使用两阶段冷启动：先在规则构建机(HK)执行
`sudo dns-stack cold-start-global`，再在国内执行 `sudo dns-stack cold-start-cn`。
普通同步 timer 不会自动接受空规则包；国内显式接受后会清空动态、Unbound 和
mosproxy 缓存，所有非人工域名暂时进入实时双路判断。冷启动包的 CIDR 文件也可以
为空，因为它们不是递归标准；新基线完成连续检测后再启用 `dns-stack-publish.timer`。

## 五、出问题怎么办

**第一步永远是**：

```bash
sudo dns-stack preflight
```

38 项逐条给出结果，失败项会附上排查命令。

### 解析不了

```bash
sudo dns-stack health                      # 先看整体
dig @127.0.0.1 -p 5335 example.com         # 绕过 mosproxy 直接问 Unbound
journalctl -u mosproxy -n 50 --no-pager    # 看 mosproxy 日志
```

如果 Unbound 能解析、mosproxy 不行，问题在 mosproxy 或证书；反之在递归链路。

### 某个网站变慢或打不开

先用命令行看它的**权威服务器在哪**——这决定了出口方向：

```bash
sudo dns-stack test 域名
```

输出会逐台列出该域名的权威及其判定（在大陆 → 直连 / 在境外 → 经隧道）。

- 权威全在境外、但你确认该站点该走直连 → 写进 `manual-cn-zones.txt` 后
  `sudo dns-stack routing-refresh`
- 权威在大陆却仍解析到境外节点 → 多半是冷启动窗口（该域名刚被第一次解析、还没
  进学习集合），等一轮或手动 `routing-refresh` 即可

### 证书过期

```bash
sudo dns-stack cert-check    # 看剩余天数
sudo dns-stack cert-renew    # 手动续签
```

正常情况 timer 会自动续，不需要手动。

### 面板打不开

不影响解析，可以慢慢修。面板、helper 都是**只读消费方**，已实测停掉它们
DNS 照常工作。

```bash
systemctl restart dns-stack-panel
journalctl -u dns-stack-panel -n 50 --no-pager
```

## 六、备份与迁移

```bash
sudo dns-stack backup                  # 立即备份
sudo dns-stack packages                # 列出所有备份/导出包
sudo dns-stack export --mode full      # 导出完整迁移包(age 加密)
sudo dns-stack verify                  # 只读校验最新的包
sudo dns-stack import <包路径>         # 导入(会覆盖本机数据，高危)
sudo dns-stack migrate root@新服务器IP  # 一键迁移
```

迁移是全自动的：检查目标机 → 备份本机 → 传包与源码（含 mosproxy 二进制，
目标机不用装 Go）→ 远程执行 install.sh → 导入数据 → 健康检查。
**旧服务器全程保持运行**，确认新机没问题后再执行 `sudo dns-stack migration-finish`。

迁移后必须做的两件事：改 `config.env` 里的公网 IP、按新 IP 重新签发证书。

## 七、有几件事要知道

**证书是 IP 证书，只有约 7 天有效期。** 这是 Let's Encrypt 对 IP 证书的策略。
续签 timer 每 6 小时检查一次，但如果服务器长时间关机超过有效期，回来需要手动续。

**分类器的规则是慢慢长出来的。** 它只收录你**实际查询过**
的域名——国内 collector 记录域名 → 规则构建节点的分类器对比国内外解析结果判定 → 发布 →
同步回来。规则尚未收录时由国内实时双路判断，不再依赖固定的 `base-cn.txt` 基线。

**不记录客户端 IP。** mosproxy 的查询日志经内存管道直接喂给 collector，
其中的客户端地址在解析后立即丢弃、从不落盘。面板展示的日志也经 helper 脱敏
（IPv4 只保留前两段）。所以面板里看不到"谁查的"，只有"查了什么"。

**面板不要暴露到公网。** 它只监听 `127.0.0.1`，走 SSH 隧道或 WireGuard 访问。
虽然所有特权操作都经受限 helper 的白名单执行、面板本身以非 root 运行，
但没必要给自己增加暴露面。

**跑的是自己修过的 mosproxy。** 仓库在 [`fa1nes/mosproxy`](https://github.com/fa1nes/mosproxy)，
以 `80afb01` 为基点修了 11 个上游缺陷、加了 5 项功能（详见该仓库的
`FORK-NOTES.zh-CN.md`）。二进制由那边打 tag 时构建发布，本仓库只下载校验。
换回上游原版会让分流在域名大小写变化时静默失效、乐观缓存退化成陈旧缓存、
缓存不按转发路由隔离，以及大部分大陆客户端整个丢掉 ECS。
升级 mosproxy 就是**在 fork 上打一个新 tag**，本仓库不用改任何东西——`install.sh` 从
`releases/latest/download` 拉最新 Release，版本号取自产物自带的 `build-id`，
再要求 SHA256 与二进制内嵌版本三者互相印证。已装的就是最新版时保留不动、不重启。
