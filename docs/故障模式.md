# dns-stack

自建 DNS 解析栈：**本地完整递归 + 递归出口按 IP 路由分流**。

目标是把 DNS 污染从「需要检测的现象」变成「结构上不可能发生」。

> 系统本身怎么运转（递归分流、规则生成与发布、部署铁律）见 [`memory.md`](memory.md)。
> 本文件是**入口与知识索引**：先读这里，需要细节再按索引跳过去。
> 日常操作见 [`docs/使用指南.md`](docs/使用指南.md)。

---

## 1. 它是怎么工作的

```
客户端 ──DoH/DoT/DoH3/DoQ──▶ mosproxy ──▶ 本机 Unbound（从根区完整递归）
                                              │
                              递归的每一跳都要问权威服务器，
                              而出口按「权威 IP 在哪」分流：
                                              │
                    ┌─────────────────────────┴─────────────────────────┐
              权威在大陆                                          权威在境外
         直连出网（境内到境内，                              经 WireGuard 隧道到香港
          GFW 不污染）                                    （GFW 看不见这个查询）
```

**两条路径都拿不到污染答案。** 于是「双视角对比 + 启发式猜谁可信」整套机制失去存在理由——
它存在的唯一前提就是"本机直连境外权威会被污染"。

判据也从主观的「这个域名算不算国内的」（要人工维护、永远滞后）变成客观的
「这台权威服务器在哪」（网络事实）。

### 节点

| 角色 | 职责 | 系统 |
|---|---|---|
| CN | mosproxy、国内递归 Unbound、collector、面板 | Debian 12 |
| HK | 10.100.0.3。境外递归出口 + 规则构建（候选拉取、分类、复检、规则生成与发布），经 WireGuard 提供出口 | Alpine（无 systemd，分类调度走 crond，见 scripts/install-hk-classifier.sh） |
| Global/SG | 10.100.0.1。**已退场**，分类/发布职责移交 HK | — |

### 关键实现

| 组件 | 作用 |
|---|---|
| `nft inet dns_route / chain output` | 正向匹配 Unbound 的 uid，目标不在 `@direct4`/`@cn_authority` 就打 fwmark |
| `ip rule fwmark 0x1d5 lookup 100` | 打了标的包走隧道 |
| `ip rule fwmark 0x1d5 prohibit` | 隧道断时境外查询**显性失败**，不回落直连（回落拿到的是污染答案，看着成功实则更危险） |
| `@direct4` | 大陆 IP 集合。源为 APNIC 一手委派记录 + qqwry 双向校正（见 §3.6） |
| `@cn_authority` | 「权威含大陆 IP」的区域；大陆权威按配置聚合，境外权威严格按 /32 直连（避免共享 anycast 误伤） |

## 2. 不可动摇的约束

这些是主人明确定过的，改动前必须回看：

- **递归方向依据答案可信度、CNAME/HTTPS 链、最终 A/AAAA、污染、DNSSEC、CDN 调度**，
  **不能依据速度**，也不能把"境外 IP"直接等同于 GFW
- **不用本系统自己观测生成的数据当判据**——原话：「那份 cidr 是自己的 dns 仓库推测出的，
  这些东西都不能确保一定准确」。选源必须是一手权威数据
- **任何路径不得出现公共 DNS**（AliDNS/114/8.8.8.8 …），包括降级路径
- IP/CIDR 不得进入**递归输入**；判定结果文件不得当作 mosproxy 输入加载
  （判定结果变判定输入 = 自我强化死循环）
- 不得 `git reset`，不得覆盖已有修改，不得输出或提交凭据
- **未经再次确认，不做生产配置替换、数据库批量修正、服务重启或 GitHub 发布**
- 验证在实机进行，不用本机 Python 试跑

完整清单见 `memory.md` §6 与 §7。

## 3. 🔴 反复出现的故障模式

**这一节是本文件的核心。** 下面每一条都不是理论，是这个项目里实际踩出来的，
而且**多数出现过不止一次**。按模式组织而不是按时间，是因为它们会以不同面孔重现。

### 3.1 静默失败：坏了也不会有人知道

本项目最危险的故障类型——**解析照常成功、rcode=0、面板全绿，答案却是错的**。

| 实例 | 表现 |
|---|---|
| `mktemp` 默认 0600 + `mv` 保留权限 | 面板一条集合都读不到，`is_cn()` 全返回 None，概览显示 0 |
| 日志目录缺 x 位 | Unbound 报一行 Permission denied 后**若无其事继续跑**，日志断了 5 天 |
| `dns-stack-geoip.service` | 自 8/2 起每天失败，GeoIP 库停更 4 天，而 health 一路全过 |
| 分流链被 `flush ruleset` 抹掉 | 境外权威全部回落直连、全拿污染答案 |
| collector 的数据库连接进坏状态 | 解析全部正常、mosproxy 指标照常涨，只有统计停在过去。**看着有数据、其实是几天前的，比一片空白更误导**（2026-08-16 才补上监测） |
| 整包被校验拒收，而脚本 `exit 0` | 规则三天没更新，systemd 眼里一切成功，面板只安静地显示"3 天前"（见 §0.2） |
| `@cn_authority` 混入境外 anycast 段 | twitter/reddit 长期返回 GFW 伪造地址（`157.240.7.20`、`2001::1`），**rcode=0、面板全绿、客户端日志无异常**，污染还被 serve-expired 续命 14 天（2026-08-22） |
| ECH 让代理拿不到真实 SNI | 域名分流规则一条都匹配不上，流量静默落到默认出站；而解析成功、握手成功、网页打得开 |

**判据**：任何"不影响解析成功率"的组件坏掉，都属于这一类。它们必须被**主动监测**，
不能指望被发现。

### 3.2 护栏保护不了自己

> 显性失败护栏（`ip rule prohibit`）与被保护对象（分流链）在**同一张 nft 表**里，
> 一起消失就一起失效。

同型实例：

- **护栏装上了，喊声传不出来**：`val-log-level` 与 `unwanted-reply-threshold` 的告警
  都写 `unbound.log`，而那个文件因目录权限根本打不开
- **护栏自身坏掉，失败伪装成被检对象的失败**：preflight 调用了未定义的函数，
  而它没开 `set -e`，`command not found` 静默变成 `||` 分支——**明明放行了却报"未放行"**
- **回归检查在读一个陈列品**：规则构建节点上有两份 `publish.py`，回归检查读的那份根本不参与执行

### 3.3 名不副实：功能没坏，是标签骗了人

- 日志「清空」只清前端显示，服务器 journal 一条没动
- 「清理陈旧域名」点了没反应——因为符合条件的是 0 个。**沉默的正确行为等同于故障**
- `dns-stack health` 把 `cn_authority` 条数**取到手了却只打印、不判断**，集合归零照样报"分流正常"
- 面板把 `rejected_cc`/`rejected_qps` 显示成两个数字却不告警——而它们非 0 就是"正在拒绝服务"

**规则：取到手的指标要么纳入判据，要么别显示。** 显示而不判断会让人以为它被看着。

### 3.4 判据用错了维度

| 错误判据 | 正确判据 | 代价 |
|---|---|---|
| 「权威的 /24 属于同一运营主体」 | 大陆权威才聚合，境外权威只认精确 IP | Route53 一个 /24 里坐着上万租户，twitter/github/netflix 被送去直连问权威、遭 GFW 注入（199/711 域名中招） |
| ECS 泄露只是**隐私**代价 | 它会让权威回一个「给中国的」地址，而那常常不可用 | sb.sb 拿到源站 = 地区限制页；91/688 域名受影响 |
| 按**字段数**选归属主源 | 按**准确度**分字段取长补短 | MaxMind 字段多但 region 恰好为空，"香港"整个丢了 |
| 拿**网段条数**当集合护栏 | 用**覆盖地址总数** | collapse 会合并相邻段，多分配几段条数反而下降 |
| 拿**合并后网段的首地址**代表整段 | 按数据源自己的网段边界判定 | 大段首地址落在境外，整段被剔，百度一起遭殃；**2026-08-23 第三次复现**——ECS 分片表把北京电信标成广东电信、上海电信标成北京联通 |
| ECS 白名单按「权威 IP 在不在大陆」收 | 按「这台权威服务谁」收（`@cn_authority`，并以 direct4 消除冷启动） | qq.com 四台权威三台在韩日港，轮询到它们就不发 ECS → 微信解析到香港腾讯云、京东跨网，且时好时坏 |
| 用**服务器可达性**代表用户可达性 | 在用户浏览器侧测 | 云主机被百度淘宝风控，服务器连不上不代表主人连不上 |

> `collapse_addresses()` 之后，**网段的任何单点属性都不再代表整段**。
> 3.4 表里第 2、3 行是同一个陷阱的两副面孔。

### 3.5 知识没有传播到邻居 —— 出现了 9 次

同一份代码里，一个地方写对了、紧邻的地方没写对。**这类缺陷 review 单文件看不出来，
只有横向对比同类结构才会浮现。**

| 对的那处 | 漏的那处 |
|---|---|
| `preflight.sh` 的 `grep -c ... \|\| true` | 另外 4 处 `\|\| echo 0` |
| `_totp_last_step` 落盘到 `/run/` | `_fails`/`_oauth_states`/`_pending_totp` 仍在内存 |
| `:has()` 用于**增强**（配色） | `:has()` 用于**布局骨架** |
| `unbound.log` 用 `touch` + `chown` | `helper.log` 用 `[[ -f ]] && chmod`（文件还没建就静默跳过） |
| `direct4` 纳入健康判定 | `cn_authority`、`rejected_*` 只显示 |
| `update-chnroute.sh` 只 chmod **文件** | `update-geoip.sh` 多 chmod 了**目录**（撞 `RestrictSUIDSGID` 必 EPERM） |
| `dns-stack health` 判定 `cn_authority` 与限流 | 面板对同两项只显示、不判断（2026-08-16 补齐） |
| `mosproxy_metrics_cached()` 有 1.5s 缓存 | 紧邻的 `unbound_stats` 裸调用，每 5 秒 fork 一次 |
| `count_lines` 用 `strip().startswith("#")` | 另一处写 `startswith("#")`，缩进注释被算成数据 |

#### 最讽刺的一种形态：守门人自己过期

2026-08-16 发现的三处，串起来是**同一件事的三层**：

- `panel/backend/app.py` 的单元清单，注释白纸黑字写着「要覆盖**所有**定时任务」，
  却漏了 `dns-stack-geoip`（正是 §3.1 表里静默失败 4 天的那个）与
  `dns-stack-routing-watchdog`（分流链最后一道防线）
- `helper` 的 `ALLOWED_UNITS` 注释写着「新增定时任务时**两边都要加**」，
  自己也漏了同样两个
- 而守着这条规矩的回归断言，**写死了一份 8 个单元的清单**，同样漏了那两个

三道防线全部失守，因为它们都靠人工同步一份会自然增长的清单。
**判据不能是清单，得是两个来源的比对**——现已改成直接 diff 面板与 helper 的白名单集合，
少一个当场引爆，而这条断言自己不会过期（§11 早就写过这条，只是没落到这里）。

### 3.6 整体替换 + 易失数据源 = 必须有骤降护栏

「整体替换」在数据源健康时是正确设计（否则陈旧数据永远留着），**数据源一空就变成破坏性的**。

- `replace_traffic_rules`：生产者一死，每轮拉取都把新判定清成空
- `update-cn-authority.sh`：`flush_infra` 清空了它唯一的数据源，30 条覆盖了积累数天的 244 条

而骤降护栏本身也踩过坑：`grep -c` 零匹配时**既输出 `0` 又返回退出码 1**，
`|| echo 0` 于是把变量变成 `"0\n0"`，数值比较语法错误并判为假——
**护栏恰好在"新结果为空"这个最该拦的场景 fail-open**。必须写 `|| true` + `${n:-0}`。

### 3.7 "改了配置文件" ≠ "修了问题"

- `/etc/nftables.conf` 里的 `flush ruleset` 改掉了，但 Debian 的 `nftables.service`
  自带 `ExecStop=nft flush ruleset`——**问题在 unit 里，配置文件里看不到**
- `bash -n` 通过 ≠ 命令拼对了：注释插进续行 `\` 之间，后半段参数会变成独立命令，
  而 `bash -n` 照样通过
- 用桩测试验证检测逻辑：桩把被测函数整个替换掉，**检测逻辑从没被执行过**

**判据只能是实测真实的引爆命令**，以及**给检测类代码喂真实输出样本**。

### 3.8 MEMORY 里的数字是快照

交接档里曾记着"6 failures + 13 errors"，实测时只剩 1 个 error，再后来是全绿。
**照着旧结论去修会凭空造出不存在的工作**——先跑一遍拿真实状态。
（正因如此，`memory.md` 现在只留长期有效的知识，不再记当时的验证数字。）

同理：`git status` 的 `M` 不代表未部署；**没有 `M` 也不代表已部署**。
判据只能是逐文件比 md5。

## 4. 日常操作

```bash
sudo dns-stack health              # 健康检查（服务 / 失败单元 / 限流 / 分流集合 /
                                   #   采集链路 / 境内外解析，逐条给出后果与恢复命令）
sudo dns-stack routing-status      # 分流状态
sudo dns-stack test <域名>         # 解析测试（显示权威归属与最终落点）
sudo dns-stack logs [unit]         # 日志

scripts/regression-check.sh        # 回归检查（每条断言对应一个真实踩过的坑）
scripts/preflight.sh               # 部署前检查
```

> 这里**刻意不写项数**。原文写着"health 9 项 / 回归 CN 172 项"，而这两个数字
> 每加一条检查就过期一次（health 的写法已经从 7 变到 9 再变到更多）。
> §3.8 说文档里的数字是快照——那条对本文件自己同样成立，所以描述覆盖面而不是计数。

面板：HTTPS，登录后可看概览 / 实时请求 / 域名统计 / 上游状态 / 规则与证书 /
解析测试 / 日志 / 运维 / 审计，并可通过 `/api/export` 导出查询、域名与规则数据（JSON/CSV）。

> 查 CDN 命中请用面板的「**我的位置与 CDN 调度**」——它在**主人浏览器里**发起，
> 视角才是对的。域名统计页的节点是面板在服务器上查的，代表不了主人的实际体验。

## 5. 数据源

**全部是一手或可追溯的外部数据，不用本系统自己观测的结果。**

| 数据 | 源 | 更新 |
|---|---|---|
| 大陆 IP 段 | APNIC 官方委派记录 | 每日 |
| IP 归属（国内） | 纯真 qqwry（ipdb 格式，`nmgliangwei/qqwry.ipdb`） | 每周 |
| IP 归属（境外 AS） | MaxMind GeoLite2-ASN | 每周 |
| IP 归属（境外地理） | MaxMind GeoLite2-City | 每周 |

### 曾经评估但**未采用**的源

- **ipip.net 免费版（`ipipfree.ipdb`）**：确认停更在 2019 年 7 月。
  ⚠️ 但"停更 = 无用"是错的——实测新旧 qqwry 差异仅 0.70% 地区 / 1.03% 运营商，
  **IP 段分配是增量的，骨干段几年不变**。不采用是因为有更新的同格式替代，不是因为它没价值。
- **GeoCN.mmdb**：中国大陆精度最好（部分到区县、带国标区划码），但数据来源是
  「二分算法扫描公开免费 API 再清洗」、随缘更新、无 License——
  属于**推测性二手数据**，撞 §2 的红线。可作参照，不进判定链。
- **DB-IP City Lite**：更新活跃、License 明确，但 124MB 且**没有 ISP 字段**
  （运营商正是判断 CDN 命中的关键），对本项目不适用。

### 归属判定：字段级取长补短

不做「记录级二选一」——**信息量不等于准确度**。

| 字段 | 取法 |
|---|---|
| `region` | qqwry 优先（国内省市实测 100%，MaxMind 约 30%），两边都空时退到 city（捞回香港这类"城市即地区"） |
| `carrier` | **云厂商 AS** > 可信范围内的 qqwry > MaxMind（AS 归属是注册事实，比第三方对接入商的标注硬） |
| `country` | MaxMind 优先（City 库是地理定位；qqwry 对境外只有粗略标注） |
| `owner` | qqwry（机构名不是地理信息，境外也常对） |
| `as_org` | MaxMind + 清洗（去掉通信地址串与 `(US)` 之类国别后缀） |

🔴 **`cn_trusted`**：qqwry 只在 `country_code ∈ {CN,HK,TW,MO}` 内可信，
这条要贯彻到**全部地理字段**——只挡 carrier 不挡 country，会输出"美国·Loyang"这种
地名对、国家错的结果。

## 7. 给下一个接手的人

三句话：

1. **先跑一遍拿真实状态**，别信文档里的数字（§3.8）
2. **改完要实测真实的引爆命令**，`bash -n` 通过和配置文件改对都不算数（§3.7）
3. **修一处时横向看一眼它的邻居**——这个项目里同一个错误平均出现 2 次以上（§3.5）
